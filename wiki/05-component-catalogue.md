## 5. Page Parts

The parts below are added to a diagram page by the descriptor, beside its symbols, pipes and sections (COB-159; the gaps GP, GM and GG of the eng02 ASM reimagining). They are written in `tools/hmi/parts.py`, with their library views in the same module and their library script in `tools/hmi/parts_script.py`; `screen.diagram_screen` places them. Every part belongs to the diagram layout: a cards page that names one, or `fit`, is refused with an error. Each works under `--render stock` and `--render module`; the module's components are used where they draw the symbol, and a symbol that carries a mark they lack stays on the library's view (section 5.5).

### 5.1 Command Buttons

A descriptor array `buttons` holds buttons: `id`, `x`, `y`, `w`, `h`, `label`, an optional `style` (`normal`, the default, or `flat`) and one `action` of three types.

Table 5. The actions of a button.

| Type | Keys | What the button does |
|---|---|---|
| `pulse` | `tag`, `ms` (100 to 600000, default 1000), `confirm` (the question) | Asks first; on Confirm, `cadre.hmi.page_pulse` writes true to the tag and, after `ms`, false |
| `faceplate` | `device`, `tab`, `kind`, `title`, `label` | Opens the faceplate of a device on a named tab, through `library.open_device` (shared contract 2.1) |
| `route` | `route` | Navigates to the route |

```json
{"id": "reset", "x": 1300, "y": 20, "w": 240, "h": 36, "label": "PLANTWIDE RESET",
 "action": {"type": "pulse", "tag": "sim/reset", "ms": 5000, "confirm": "Reset the plant?"}}
{"id": "alarms", "x": 1000, "y": 80, "w": 130, "h": 36, "label": "Pump alarms",
 "action": {"type": "faceplate", "device": "P1", "tab": "alarms"}}
```

A pulse is never written on the first press. The press shows the question with Confirm and Cancel in the button's place (P10, as the Confirm row of a faceplate does); Confirm calls `cadre.hmi.page_pulse(self.session, <path>)`. The function uses write path W18, so the administrator role is asked first and a session without it learns nothing of the project's tags. It writes only a tag listed in `session.custom.commands`, which the generator writes from the descriptors (`parts.commands_index`): a script never writes a tag the descriptors did not declare. The same tag with two lengths is an error. The buttons that can reach the call bind `enabled` to `{view.custom.can.W18}`, which gate G7 commands requires and checks; the check inside the function is the control (GF-59). A refusal shows as the button's text until the next press.

For a `faceplate` action, `device` is the id of a symbol of the page that is marked `device`, or a device folder under `tagRoot`; for a folder that no symbol of the page draws, `kind` is required. The device must be marked `device` by some symbol of the page set, or the build reports an error. `tab` is a tab key of the faceplate; a key it lacks opens the first tab.

### 5.2 Range Bars

The view `Parts/RangeBar` (shared contract 2.3) has the parameters `value`, `min`, `max`, `normalLo`, `normalHi`, `loLimit`, `hiLimit`, `unit`, `format` and `vertical`, and `showValue`, which adds the value and unit beside the bar. A null number is absent. The bar is one `ia.shapes.svg` whose elements `cadre.hmi.range_bar_elements` lays out from the parameters, so that it scales to any box: the track, the normal band, a mark at each limit and the value marker, which takes the warning colour beyond a limit and no colour otherwise (P4). The figures reach the script as text written by `toStr`, never `numberFormat`, so that the session's locale cannot change them.

A bar is placed in two ways. Beside a readout or an instrument field, the symbol takes a `bar` key, and no position of the descriptor moves; the value is the symbol's bound `value`.

```json
{"id": "RD2", "kind": "readout", "x": 40, "y": 110, "w": 72, "h": 24, "bind": {"value": "gen/fuel"},
 "params": {"unit": "%", "format": "#,##0", "label": "Fuel"},
 "bar": {"min": 0, "max": 100, "loLimit": 40, "side": "right", "length": 120}}
```

`side` is `right` (default), `left`, `below` or `above`, against the readout's box as the library gives it (`screen.symbol_box`); `length`, `thickness` and `gap` are in px, and `x`, `y`, `w` and `h` place the bar outright. Elsewhere, the array `bars` holds a bar with its own box and a `value` member: `{"id": "load", "x": 40, "y": 160, "w": 200, "h": 12, "value": "gen/load", "min": 0, "max": 100, "normalLo": 20, "normalHi": 80, "hiLimit": 90}`. The limits are fixed numbers of the descriptor. A faceplate that needs a bar leaves `# COB-159 bar here` and embeds `Parts/RangeBar` (shared contract 2.3).

### 5.3 Embedded Trends

The array `trends` holds a trend: `id`, `x`, `y`, `w`, `h`, `title`, `minutes` (default 10) and one or two `pens`, each with `tag`, `label` and `unit`. The part is the library's stock time series chart over the tag history of the pens, in one of three views chosen from the pens: `Parts/Trend` (one pen), `Parts/Trend2` (two pens, the one value axis) and `Parts/Trend2Axes` (two pens whose units differ, an axis each at the left and the right). The chart is `framework.trend_chart`; the history binding takes its tags from a view property that holds a list of path objects (gate G7 history).

```json
{"id": "tr1", "x": 40, "y": 190, "w": 340, "h": 140, "title": "Engine speed and voltage", "minutes": 10,
 "pens": [{"tag": "gen/speed", "label": "Speed", "unit": "rpm"}, {"tag": "gen/voltage", "label": "Voltage", "unit": "V"}]}
```

Table 6. What a pen's tag needs in an external tag model.

| Key | Value |
|---|---|
| `historyEnabled` | `true` |
| `historyProvider` | The name of a history provider the gateway has |
| Sampling | On change or periodic; the chart interpolates between samples |

History set on a reference tag records, where its source with no history keys records nothing (GF-53). A tag model passed to the generator is searched for each pen's tag (`screen.historised`), and the build says in the page's notes which pens it does not historise. A generated test build writes memory tags without history, so its trends draw nothing.

### 5.4 Line Styles

The array `lines` holds a line: `id`, `points` (at least two `[x, y]` pairs), `width` (default 2), `style` (`solid` or `dashed`) and an optional `gate`. A line with `"style": "dashed"` is the static dashed line of the ATS interlock. With a `gate`, a tag member or a symbol of the page (or a list of them, all of which must hold), the line is solid while energised and light and dashed while dead, so the state is in the stroke and not only in its colour (P4). Lines are drawn with the pipes, beneath the symbols.

```json
{"id": "bus1", "points": [[724, 450], [724, 600], [1100, 600]], "width": 3, "gate": {"symbol": "SW1"}}
{"id": "interlock", "points": [[724, 520], [884, 520]], "style": "dashed"}
```

A symbol gate reads the same view property as the pipes (`custom.g_<symbol>`); a tag gate adds one tag binding to the view.

### 5.5 Duty and Out of Service Marks

Every automation symbol view (pump, motor, fan, valve, analogue valve, damper, filter, switch, indicator) gains two parameters. `badgeDuty` shows the package's `duty` icon as a 16 px badge at the bottom centre, between the interlock and command locked badges. `outOfService` draws a veil of the page colour over the symbol (72 per cent) and the word OOS, under the badges and the alert frame. Either is stated, or bound to a tag member:

```json
{"id": "P1", "kind": "pump", "x": 700, "y": 80, "w": 48, "h": 48, "device": true,
 "bind": {"on": "P1/state", "badgeDuty": "P1/duty", "outOfService": "P1/oos"}}
```

The module's components have neither mark. A symbol that states or binds one therefore stays on the library's view under `--render module` (`screen.module_draws`); a symbol that does not is drawn as before.

### 5.6 Fault Rows

An indicator symbol takes an `alarm` key, the tag whose alarms the lamp follows. The lamp's alert frame then follows them through the library's alert states (F016): one `custom.alerts` entry per row, answered by one `cadre.hmi.alert_states` query for the whole page, with the key value `tag:<path>`, which `cadre.hmi.device_sources` turns into the source pattern `prov:<provider>:/tag:<path>:/alm:*` (the source form of GF-34). A condition that does not hold is the lamp's empty ring, with no colour; one that holds shows the lamp filled, its text bold and its priority shape (triangle, circle or square), and the frame flashes until the alarm is acknowledged. The generator leaves the row's `hasTag` and `showStatus` as the descriptor states them, since the toolbar's ID tag button must not hide a condition's text.

```json
{"id": "FL1", "kind": "indicator", "x": 40, "y": 410, "w": 48, "h": 48, "alarm": "gen/fault01",
 "bind": {"on": "gen/fault01"},
 "params": {"readoutPosition": "right", "hasTag": true, "tag": "Low oil pressure", "showStatus": false}}
```

### 5.7 Scale to the Window

The screen option `fit` scales a diagram to its window: `true`, or `{"reserveX": n, "reserveY": n}`. The diagram stays a box of its own width and height and takes a CSS `transform` of `scale(k)` from its top left corner, where `k` is the smaller of the viewport's width and height over the page's, less the pixels the frame takes (`reserveY` defaults to the top dock, 48 px, and the toolbar, 56 px, or 48 px without a toolbar; `reserveX` to 0), and never above 1. The viewport is Perspective's `page.props.dimensions.viewport`. The canvas stops scrolling. A 1580 by 740 page keeps its size at 1600 by 900, where it needs no scrolling, and scales to 0.81 at 1280 by 800 (the width decides). A coordinate container in percent mode with an aspect ratio was not used: it scales the positions of its children and not the embedded views, whose symbols hold their sizes in px. The viewport keeps its width while a dock pushes the page (measured on 8.3.6, 2026-10-24: with the 400 px faceplate dock open, a fitted page kept its scale and lost its right edge), so the library's scripts that open and close the faceplate dock keep `session.custom.faceplateDocked` (`library.DOCKED`: the opener, the dock's Float pin and close button, the popup's Dock pin), and the width term subtracts 400 px while it is true (`parts.FIT_DOCKED`). On the eng02 Generator-1 page the scale goes from 0.90 to 0.76 when the dock opens, the page's right edge at the dock's left edge, and back when the faceplate floats. A browser reload that keeps the session while the dock closes leaves the flag true until the next open or close; the page is then drawn smaller, never cut.

### 5.9 Checks and Gates

The schema (gate G0) refuses an unknown key, a pulse outside 100 ms to 10 minutes, a trend of three pens, a line of one point and a mark level above 1. The generator refuses a repeated part id, a part on a cards page, a bar without a value, `alarm` on a symbol that is no indicator, `bar` on a symbol that is no readout or field, a faceplate button for a device no page marks, a gate or an emphasis on a symbol with no state, a link to an icon the library lacks, and well marks that do not rise. Gate G7 commands requires each control that calls `page_pulse` to bind `enabled` to the permission of W18. The library profile states the parts under `parts` (`library/profile.json`).
