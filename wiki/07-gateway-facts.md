## 3. Feedback for the Ignition-Wiki

1. **Validator gap (GF-07).** `validate_view.py` does not check view-level `propConfig` keys. A
   check that each key starts with `custom.` or `params.` would have caught GF-07 offline.
2. **Validator success (registry gate).** The validator caught an undeclared tag binding key
   (`fallbackDelay`) written from recall before the view reached the gateway.
3. **Visibility semantics (GF-08).** IGW:27 section 7.3 records `visibility: hidden` for a hidden
   component; the consequence for flex layouts and the `position.display` alternative belong next
   to it.
4. **Inheritance at runtime (GF-01, GF-02, GF-10).** IGW:01 section 9 records that the runtime effect
   of `parent` and `inheritable` is not described by the sources; these three facts describe it.
5. **Trial reset (GF-03).** The licensing route resets the trial; the earlier sandboxes treated the
   trial page as needing a manual web reset (Cadre-Sandbox-SCADA DEF-08).
6. **Expression tag simulation (GF-16 to GF-19).** Self reference, alarm properties in tag
   expressions and the null start up behaviour are not recorded in the registry; a page on
   simulating a process with plain tags would carry them, with `coalesce` as the rule.
7. **Acknowledge in gateway scope (GF-21).** IGW:22 section 3.1 records the gateway overload; a note
   that the two argument form acknowledges nothing in a Perspective script belongs next to it.
8. **Modules (GF-27 to GF-31).** The registry records module components (the `embr.*`
   schemas) but not the install route sequence, the restart it needs, or the version format; a page
   on building and installing a Perspective module would carry them.
9. **Reference and derived tags (GF-46 to GF-50, GF-53).** IGW:26 section 5 records the two value sources
   from two and four exported nodes and says nothing of reading, writing, quality or history; these six
   facts describe them, and `deriveExpressionGetter` is not named in the page.
10. **UDT definitions (GF-51, GF-54).** IGW:26 section 8.1 calls `_types_` a convention of the exports; on
    the gateway a definition outside the provider's `_types_` folder is dropped silently. The parameter
    form, attested there for `opcItemPath` and `value`, also works on `sourceTagPath` and `expression`.
11. **Alarm source patterns (GF-52).** IGW:22 section 3.1 documents `source` as a list and the component
    page documents commas for the table; the comma form does not work in the script call.
12. **Tag import (GF-55).** IGW:28 records the import route and the Overwrite policy; that it merges at
    folder level and replaces at tag level belongs beside it.
13. **Tag event scripts (GF-57).** No page records the `eventScripts` key of a tag document, the
    names in scope of a value-changed script, or that the body may write tags.
14. **Unattended commissioning (GF-99 to GF-103).** A page on running the 8.3 image headless would carry the commissioning
    variables, the JVM property for unsigned modules, the API token as a configuration resource with its hash form, the refused
    `Authenticated/Roles` grant and a custom security level instead, and the stored form of a user's password.
15. **Module trust and restarts (GF-105 to GF-107).** IGW:28 records the install route; that a first install of an unsigned module
    waits at a commissioning step, the call that trusts it, and that an upgrade needs none, belong beside it.
16. **History provider by REST (GF-104).** The resource routes create a database connection and an SQL historian without the web
    interface and without a restart.
